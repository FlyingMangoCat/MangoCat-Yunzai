# MangoCat-Yunzai 插件生态与兼容契约 v0.1

> 状态：草案（v0.1）
> 维护：MangoCat-Yunzai 主线
> 适用：本运行时（icqq / OneBotv11 / 其他适配器）与所有第三方插件
> 一句话：**兼容有基线，收录有门槛，排名有规则，改规则有程序。**

---

## 0. 元规则：规则怎么定、怎么改、怎么退

1. **由主线起草与维护**：本文件由主线起草（不点个人名），日常收录、审计、排序由自动化规则执行，不逐案拍板。
2. **规则先于案例**：不为某个具体插件临时加规则；新规则不溯及既往。
3. **红线少而硬**：安全红线只保留少数几条，写死、不解释、对本体同样适用。
4. **默认无异议通过**：修订公示 7 天，无有资格者反对（须附理由）即通过。不搞日常表决，省组织成本。
5. **投票只兜底**：仅「削弱 L1 兼容」「删除安全红线」两类，且需 ≥2 名有资格者联署异议才启动；防拉票见 7.2。
6. **可退**：规则只约束「决定」，不约束「人去留」。主线可随时修订、移交或退出，任何条款不得阻止。
7. **紧急处置权**：遇恶意刷票、大规模投毒等紧急情况，可先处置、后公示，7 天内补理由并接受复核。
8. **枷锁要轻**：能自动化的不写成人治条款；规则每年清理一次，只留必要项。
9. **可申诉**：任何收录、降级、移除决定，均可按同一套规则重审。

## 1. 社区宪章

1. 门槛在契约，不在人。
2. 信任靠计算，不靠背书。
3. 可见性靠规则，不靠关系。
4. 核心开放，边界由契约划定。
5. 后门 / 恶意代码 / 混淆 / 伪开源 / 闭源核心 = 明确红线，不解释。

## 3. 新规定 · 可选升级（L2 / L3）

**定义**：**跟进有收益，不跟进不惩罚。** 目标是让插件可被机器校验、可被隔离、可持续。

### 3.1 L2 · 契约合规

- `plugin.yaml` 清单：`name / version / entry / author / source / permissions`
- 权限声明：`fs`（路径范围）/ `exec`（允许命令）/ `net`（域名白名单）/ `master`（是否需主人）
- 安全红线：无隐藏授权哈希、无远端下载后 eval、无硬编码密钥、无写死 QQ 授权
- 渲染规范：只用 `e.runtime.render`，不直接写 `temp/`
- 不越界：不修改全局原型、不私改 `config/`
- 校验：静态审计 + 版本哈希 + 台账比对

### 3.2 L3 · 隔离就绪（实验）

- 声明 `isolation: worker | process`
- 不依赖进程内全局，改由注入接口
- `fs` / `exec` / `net` 仅在声明权限内生效
- 说明：运行时沙箱尚未落地，本层暂为实验，不作承诺

## 4. 安全门（收录硬门槛）

**审计不通过 = 不收录 = 不参与排名。** 命中任一条直接出局，不能用分数挽救：

- 后门 / 隐藏授权哈希 / 写死他人 QQ 授权
- 无权限门禁的 RCE、任意命令执行、动态执行用户输入
- 硬编码真实密钥 / Cookie / 密码
- 未声明的用户数据外传
- 远端下载后解码执行（remote eval）
- 闭源二进制核心 / 无法解释的混淆执行体
- 恶意 install 钩子 / 供应链投毒

复核：审计可复算；结果连同**版本哈希 + 日期**写入台账；申诉可重审，规则不变。

## 5. 收录与排名

### 5.1 排名池与层级

过安全门才进池。池内按**合规度**分层，作为第一排序键：

| 层 | 条件 |
|---|---|
| L3 | manifest + 权限声明 + isolation |
| L2 | manifest + 权限声明 |
| L1 | 已过安全门，无 manifest |

层 ≠ 安全度。池内所有人都已安全；层只表示对新规定的跟进程度。

### 5.2 层内公式

```
Score = 0.6·R + 0.3·U + 0.1·A + P
```

| 项 | 定义 |
|---|---|
| `R` 口碑 | `min(1, log(1+stars) / log(1+K))`；K：GitHub 1000 / Gitee 300 |
| `U` 更新 | ≤6 月 1.00；6–12 月 0.75；1–2 年 0.50；>2 年 0.25（只加不扣） |
| `A` 资历 | `min(1, 首提交年数 / 3)` |
| `P` 修正 | 过时依赖 −0.20；不兼容当前版本 −0.30；下限 −0.50，不为正 |

**不变量**

1. 评分不能越层（L1 刷到满分也压不过 L2）
2. 维护频率不进正分（稳定完成态不扣分）
3. 公式可解释（展示 R / U / A / P 分项）

### 5.3 star 快照与降级链

star 是**月度快照**，写入台账（含 `snapshot_date`），排序读快照，不实时请求。

| 情况 | 取值 |
|---|---|
| 独立仓库 | 平台内 star，按平台 K 归一 |
| 集合仓单 JS | `仓库 star ÷ 该仓收录插件数`，标「集合收录」 |
| 无仓库 / 0 星 | 资历 + 名称兜底，不给负分 |
| 异常暴涨 | 记录、降权、人工复核，不自动封禁 |

### 5.4 对抗

- 刷星：异常检测 + 封顶，不引入复杂风控
- 冷启动：用「最新收录」独立曝光窗补偿
- 跨平台：Gitee / GitHub 分平台归一，不混量纲

### 5.5 并列与曝光

- 同分 → 资历 → 名称（确定性，不随机）
- 「最新收录」独立标签页，30 天窗，不进主分
- 精选位轮换，不永久置顶
- **维护者自产插件：同公式；并列时排最后；不进精选位**

### 5.6 可解释

每个条目展示：`口碑 R（star 数）/ 更新 U（最后提交）/ 资历 A（首提交）/ 修正 P（标签）`。

## 6. 呈现层

1. **中性默认**：默认排序与质量无关、可解释；明示「默认 ≠ 推荐」，用户可切换排序。
2. **可解释**：任何顺序都能回答「为什么它在当前位置」。
3. **头部轮换**：精选位轮换，新人有时间窗。
4. **搜索优先**：标签与搜索直达，弱化「排第一」的价值。

## 7. 治理

### 7.1 决策

- **默认无异议通过**：提案公示 7 天，无有资格者反对（须附理由）即通过。
- **投票兜底**：仅「削弱 L1 兼容」「删除安全红线」两类，且需 ≥2 名有资格者联署异议才启动。
- **版本**：本文件 `v0.x`；破坏性改动升 minor，提前一个版本公告。
- **失效**：标「可演进」的项，告警 ≥2 个版本再移除。
- **申诉**：收录 / 降级 / 移除均可重审，规则不变。
- **调参**：权重公开；调整即升版本并公示 Top N 变化。
- **底线**：新规定只加不减，不得反向破坏 L1。

### 7.2 投票防拉票（仅在启动投票时适用）

- 资格绑仓库所有权（真作者才算），不认匿名号、当天新号。
- 一人一票，单人权重封顶（≤ 总票 10%）。
- 固定 7 天窗口，开始后不加人。
- 公开计票、可复核；禁止代理 / 代投。
- 法定人数：有资格者参与率 ≥50%，否则结果无效。
- 允许公开拉票（透明），禁止有偿 / 交易票。
- 异常集中投票触发复核，结论公开。

## 8. 提案与反馈

- 新想法、规则修订、纳入新方向，**统一走 Issue**，不在群聊里口头定。
- 模板：`.github/ISSUE_TEMPLATE/proposal.md`（Gitee 用户复制正文即可）。
- 提案写清：问题 / 方案 / 影响面（兼容性、安全）/ 是否愿意实现。
- 纳入条件：≥1 个真实插件提案；不纳入的，公开理由。
- 方向不预设（配置 schema、插件依赖、`onUpgrade`、健康检查、模板版本），按提案走。

## 9. 如何跟进（给插件作者）

1. 过安全门：确保无第 4 节任一红线。
2. 加 `plugin.yaml`：填 `name / version / entry / author / source / permissions`。
3. 声明权限：`fs / exec / net / master` 按实际填写，宁少勿多。
4. 渲染走 `e.runtime.render`，不直接写 `temp/`。
5. 提交后由自动化审计校验；通过即进入 L2，获得推荐位与文档收录。
6. 有隔离能力再声明 `isolation`，进入 L3。
